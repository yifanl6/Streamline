How to use Streamline

Start here

Turn a community decision into accountable work.

Streamline sits on top of a Sputnik DAO treasury. The DAO still controls the funds and approvals; Streamline gives the community a practical workflow for defining work, limiting how money may be used, reviewing a deliverable privately, and linking reputation to completed work.

What you need before starting

Reading the public dashboard requires nothing. Running the complete demo requires the operator credentials and configured integrations.

For visitors
No wallet or login is required to view tasks, budget summaries, DAO state, or reputation records.
For operators
Copy STREAMLINE_ADMIN_TOKEN from the hosting environment and enter it under Build & fund. The token remains in the current browser tab.
For DAO data
The server needs the public Sputnik DAO account ID. Streamline reads policy, bounties, and proposals without holding a DAO private key.
For private review
The server needs a funded NEAR AI Cloud API key. The selected model must support hardware attestation and signed responses.

Choose how you are using it

The interface exposes different parts of the workflow depending on your role.

Community member

Follow the money

Use Overview to see which work is open, how much budget remains, and what the connected Sputnik DAO reports. These are read-only actions.

Contributor or agent

Take accountable work

Choose an open task and associate it with a named NEAR account. The account becomes part of the task and eventual receipt trail.

DAO operator

Define safe boundaries

Use Build & fund to register a program, restrict approved services and recipients, post tasks, and review work before settlement.

Complete walkthrough

For a hackathon demo, follow these steps in order so each screen has the information needed by the next one.

1

Confirm the treasury connection

Open Overview and select Sync DAO. Streamline reads the configured Sputnik contract and shows the role count, proposal bond, bounty count, and proposal count.

If this fails, confirm that the DAO ID and RPC URL are on the same NEAR network.

2

Unlock the operator session

Open Build & fund, paste the hosted STREAMLINE_ADMIN_TOKEN, and select Unlock. This authorizes administrative API requests only for the current browser tab; it is not a wallet private key.

3

Register a bounded program

Choose a program ID and reference the DAO bounty ID. Enter the total available amount, expiration, payment network, and asset.

Allowed payees control who may receive funds. Allowed services control what type of agent work the budget may purchase. These restrictions are checked before signing.

4

Post and claim a task

After the program appears in the selector, describe one concrete piece of work and post it. The task appears publicly in Overview.

Claim associates the work with a named NEAR account. In this prototype, the operator authorizes the claim; a production version would replace that step with wallet authentication.

5

Review the deliverable privately

Open Privacy & trust. Write explicit acceptance criteria, then paste the deliverable. Streamline first verifies fresh Intel TDX and NVIDIA GPU evidence, sends the work only after verification, and checks the signed response.

The dashboard returns a pass/fail decision, reasons, content hashes, and verification checks. Streamline does not store the plaintext criteria or deliverable.

6

Authorize settlement within policy

A task capability can restrict the recipient, service route, per-call value, total value, number of calls, and expiration. A request outside those boundaries is rejected before a wallet signature is created.

Sputnik remains the approval and treasury layer; Streamline does not replace the DAO multisig.

7

Inspect receipt-backed reputation

Use the reputation lookup with a named account. Reputation is derived from signed completion receipts, so a score can be traced to actual completed work rather than an unverified profile claim.

What remains public and what stays private

Public
DAO account ID, tasks, budget totals, policy summaries, hashes, verification outcomes, receipts, and reputation evidence.
Private
Admin token, NEAR AI API key, wallet recovery material, acceptance criteria, and deliverable plaintext.
Never enter here
A Meteor recovery phrase or NEAR private key. Wallet approval should happen inside the wallet, not in this dashboard.
Free-host note
The current server keeps programs and tasks in memory. A free-host restart can clear demo records, while Sputnik DAO data remains on-chain.
